# Cache TTL Reference (source of truth)

**Issue:** #1062 · **Audience:** operators and indexer contributors · **Scope:** documentation, env-example comment, static test

This table is the source of truth for how long each Redis-backed response can
be stale. It is generated by reading `indexer/src/api/routes.ts` and the `TTL`
constant in `indexer/src/cache-warmer.ts`.
`indexer/src/__tests__/redis-ops-docs.test.ts` parses both files and this
table, and fails if they drift.

Any route not listed here (for example `/wallets/:address/activity`,
`/offers`, `/stats`, `/search`) is **not** response-cached and always reads
PostgreSQL.

## 2. Other TTLs

| Key | TTL | Configured by | Default |
|---|---|---|---|
| `activity:recent` (`getCached`) | 30 s | `TTL.ACTIVITY_RECENT` | 30 s |
| `collection_fee:<address>` (`getCached`) | 30 s | literal in `routes.ts` | 30 s |
| `lock:<key>` | fetch timeout + 1 s | `CACHE_FETCH_TIMEOUT_MS` | 30 000 ms → 31 000 ms |
| Lock wait (loser) | — | `CACHE_LOCK_WAIT_MS`, `CACHE_LOCK_POLL_MS` | 5 000 ms, 50 ms |
| `abuse:quota:*` | 60 s | `FAMILY_BUDGETS[*].windowSeconds` (code) | 60 s |
| `abuse:block:*` | block duration | `ABUSE_BLOCK_DURATION_SECONDS` | 900 s |
| `sse:events` | none (length cap) | `SSE_STREAM_MAXLEN` | 1000 entries |

`TTL.METRICS` (15 s) is declared in `cache-warmer.ts` but no route uses it.

## 3. Reconciled discrepancies

| Where | Was | Actual behavior | Fix in this change |
|---|---|---|---|
| `indexer/README.md` "Redis Caching" | `/listings` 30 s, `/auctions` 30 s | 10 s each | README now links here and shows the real values |
| `indexer/README.md` | `/wallets/:address/activity` 15 s | not cached | row removed |
| `indexer/.env.example` | `REDIS_CACHE_TTL_SECONDS=30` described as "TTL for API responses" | Parsed into `CACHE_TTL_SECONDS` in `routes.ts` but never used. Changing it has **no effect**. | comment corrected; the variable is kept so existing deployments do not break |
| `load-tests/docker-compose.load-test.yml` | `REDIS_CACHE_TTL_SECONDS: "10"` | no effect (same reason) | noted only |

Making `REDIS_CACHE_TTL_SECONDS` take effect would be an application-code
change. That needs its own issue.

## 4. Verifying a live TTL (read-only)

> **READ-ONLY.** `TTL` and `GET` do not modify keys.

```bash
# Prime the key, then read its remaining TTL. It should be ≤ the table value.
curl -s -o /dev/null "$INDEXER_URL/listings/42"
redis-cli -u "$REDIS_URL" TTL 'cache:/listings/42'
```

## 5. Validation, review, revert

- **Validate:** `cd indexer && npx vitest run src/__tests__/redis-ops-docs.test.ts`
- **Review:** if a PR changes `cacheMiddleware(...)` or `TTL`, the test fails
  until this table is updated. Reviewers check the new TTL is acceptable
  against the staleness budget in [redis-outage.md](./redis-outage.md).
- **Revert:** `git revert <commit>`. The only non-doc changes are a comment in
  `indexer/.env.example` and a static test, so there is no runtime effect.

# Incident records

Post-incident write-ups live here as `YYYY-MM-DD-<short-type>.md`. Use the templates in
[`docs/runbooks/`](../runbooks/README.md) and [`docs/INCIDENT_RUNBOOK.md`](../INCIDENT_RUNBOOK.md).

Each record must include a **Backlog follow-up** section per
[`docs/reliability/quarterly-review-process.md`](../reliability/quarterly-review-process.md#6-incident-and-near-miss-backlog-rules)
so incidents and near misses update the [reliability backlog](../reliability/backlog.md) or close
GitHub issues with explicit rationale.

There are no filed incidents in the repository yet; tabletop outcomes are tracked in
[`tabletop-exercises.md`](../runbooks/tabletop-exercises.md) until a production incident occurs.
